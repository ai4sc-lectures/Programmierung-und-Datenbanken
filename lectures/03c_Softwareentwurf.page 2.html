Von der Anforderung zum Code

Bevor eine einzige Zeile Code geschrieben wird, muss klar sein, was das Programm leisten soll und wie es strukturiert werden soll. Dieser Abschnitt zeigt, wie die Lücke zwischen einer Anforderung des Auftraggebers und einer Zeile Python geschlossen wird — und warum dieser Entwurfsschritt entscheidend ist.

Die Phasen der Softwareentwicklung

Ein strukturiertes Vorgehen ist essentiell, weil es Teamarbeit ermöglicht, Qualität sicherstellt und Kosten kontrollierbar macht. Ohne systematische Planung entstehen oft chaotische Entwicklungsprozesse, die zu fehlerhafter Software, Terminüberschreitungen und Budgetproblemen führen.

Anforderungsdefinition

Die erste Phase dient der präzisen Definition dessen, was die Software leisten soll. Hier werden sowohl die funktionalen Aspekte als auch die Randbedingungen festgelegt.

Entwurfsphase

Der Entwurf definiert, wie die Software strukturell aufgebaut werden soll — Klassenmodell und Ausführungsplanung: Was wird wann, durch wen, und wie implementiert.

Ausführungsphase

Die Ausführung umfasst die Implementation der einzelnen Softwarekomponenten und deren Integration zu einem funktionsfähigen Gesamtsystem.

Abnahme und Test

Die Abnahmephase stellt sicher, dass die fertige Software alle Anforderungen erfüllt — durch Modul-, Integrations- und Systemtests.

Vorgehensmodelle

Software wird heute fast ausschließlich im Team über längere Zeiträume entwickelt. Unterschiedliche Projekttypen erfordern unterschiedliche Vorgehensmodelle — das richtige Modell zu wählen ist selbst eine Entwurfsentscheidung.

Wasserfallmethode — Das traditionelle Entwicklungsmodell

Die Wasserfallmethode repräsentiert den traditionellen Ansatz der Softwareentwicklung und wird noch heute häufig in Ausschreibungen großer Systeme gefordert. Ihr charakteristisches Merkmal ist die streng sequenzielle Abarbeitung der Entwicklungsphasen, wobei jede Phase vollständig abgeschlossen werden muss, bevor die nächste beginnt.

Der große Vorteil liegt in der Planbarkeit und dem strukturierten Vorgehen. Allerdings führt die sequenzielle Natur dazu, dass Fehler aus frühen Phasen erst sehr spät entdeckt werden.

V-Methode — Entwicklung mit systematischer Testplanung

Die V-Methode wurde speziell für die Entwicklung sicherheitskritischer Software konzipiert. Das charakteristische V-förmige Modell trennt Entwicklungs- und Testaktivitäten klar voneinander, wobei Tests bereits im Entwicklungsarm definiert werden.

Agile Methode — Flexibilität durch iterative Entwicklung

Die agile Methode stellt eine moderne Antwort auf die Herausforderungen sich schnell ändernder Anforderungen dar. Anstatt ein komplettes System von Anfang bis Ende zu planen, wird schrittweise entwickelt und kontinuierlich verbessert.

Der agile Ansatz beginnt mit einem Minimal Viable Product — einer einfachsten funktionsfähigen Version. Diese wird in regelmäßigen Zyklen (typischerweise alle 3 Monate) erweitert und verbessert.

Agentischer Entwicklungs-Loop — das vierte Modell

Der agentische Entwicklungs-Loop ist ein modernes viertes Vorgehensmodell, das die Verfügbarkeit von KI-Coding-Assistenten voraussetzt. Er folgt dem gleichen iterativen Rhythmus wie die agile Methode, aber die KI übernimmt die Implementierungsphase.

Mapping auf den agilen Rhythmus:

  • Sprint Planning → Prompt formulieren (Anforderungsspezifikation)
  • Sprint (Implementierung) → KI generiert Code
  • Sprint Review → Mensch versteht und testet Code (Verifikation)
  • Retrospektive → Prompt verfeinern, nächste Anforderung

Kernkompetenz im agentischen Loop: Nicht Tippen, sondern Verstehen und Verifizieren ist die Schlüsselkompetenz. Die KI generiert immer Code — ob dieser korrekt ist, liegt beim Ingenieur.

Der agentische Loop wurde in 01c_AgentischesProgrammieren eingeführt. Hier sehen wir ihn als formales Vorgehensmodell im Software-Engineering-Kontext.

UML Klassendiagramme

Im objektorientierten Softwareentwurf wird ein Programm so entworfen, dass es aus interagierenden Objekten besteht. Hierbei verwendet man die Modellierungssprache UML um Klassen visuell zu entwerfen.

In diesem Kurs nutzen wir UML-Klassendiagramme als Brücke zwischen Anforderung und KI-Prompt: Wer sein Klassenmodell als UML zeichnen kann, kann es auch in einen präzisen Prompt übersetzen.

Hinweis: In 04c_Objects (S04) wird das hier eingeführte UML auf konkrete Python-Klassen angewendet.

Klassen, Attribute und Methoden

Eine Klasse wird als Rechteck mit drei Ebenen dargestellt. In der ersten Ebene steht der Klassenname. In der zweiten Ebene werden alle Attribute mit ihrem Datentyp aufgelistet. Die dritte Ebene enthält alle Methoden mit ihrer vollständigen Signatur.

Referenzen

Eine sehr wichtige Arbeit mit UML ist die Visualisierung von Abhängigkeiten zwischen Klassen in Form von Referenzen. Man unterscheidet in UML die Referenzen in der Art der Besitzverhältnisse: ob ein Objekt Teil eines anderen ist und ohne ihn existieren kann (Aggregation) oder nicht ohne diesen existieren kann (Komposition) oder komplett unabhängig ist (Assoziation).

Vererbung

Ein wichtiger Aspekt in der Arbeit mit UML ist die Vererbung. Die Vererbung wird in UML durch eine Referenz mit einem gefüllten Dreieck “▲” bei der Oberklasse gezeichnet.

BIM Anwendungsbeispiel: Anforderung → UML → KI → Code

Dieses Beispiel führt den vollständigen agentic workflow durch: von einer natürlichsprachlichen Anforderung über ein UML-Klassendiagramm zu einem KI-generierten Python-Programm. Die Verifikationsphase zeigt, wie man prüft, ob der generierte Code das Diagramm korrekt umsetzt.

Das UML-Klassendiagramm für das BIM-Beispiel identifiziert drei Klassen: Building, Room und Window. Building enthält einen oder mehrere Rooms (1 zu 1..), jeder Room hat null oder mehr Windows (1 zu 0..).
