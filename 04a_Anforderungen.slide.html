Anforderungen festlegen

Drei Arten von Anforderungen

Funktional

Ergebnis, Verhalten oder Interaktion, die ein System liefern soll

  • Der Mittelwert wird zeitgewichtet berechnet
  • Ein Messwert −999 wird ignoriert

Qualität

Qualitätsaspekte, die die funktionalen Anforderungen nicht abdecken

  • Auswertung eines Tages dauert höchstens 1 s
  • Das System bleibt bei Sensorausfall betriebsbereit

Randbedingung

Beschränkt den Lösungsraum über das Nötige hinaus

  • Nur die Python-Standardbibliothek
  • Ausgabe im Format des Warnsystems

Eine einzelne Anforderung prüfen

Sechs Kriterien (IREB)

  • Angemessen: beschreibt echte, abgestimmte Bedürfnisse
  • Notwendig: gehört zum Umfang des Systems
  • Eindeutig: alle verstehen dasselbe
  • Vollständig: nichts zum Verständnis fehlt
  • Verständlich: die Zielgruppe versteht sie
  • Prüfbar: Erfüllung lässt sich eindeutig feststellen

Umschreiben

„Die Auswertung soll schnell und einfach sein.“

„WENN ein Tagesbericht angefordert wird, muss die Auswertung für 144 Messwerte (24 h im 10-Minuten-Raster) in höchstens 1 s ein Ergebnis liefern.“

Der Zahlenwert ist ein Beispielwert, nur die 144 folgen aus dem Messraster.

User Story und Akzeptanzkriterien

Schablone

Als [Rolle] möchte ich [Anforderung], damit [Nutzen].

Akzeptanzkriterien legen fest, wann die Story erfüllt ist.

Beispiel

Als Betreiber möchte ich den mittleren Wasserstand je Tag, damit ich Berichte ohne Handrechnung erstellen kann.

  • Gegeben Messwerte bei 0, 1, 2 und 6 h mit 2,30; 2,32; −999; 2,60 m, wenn der Mittelwert berechnet wird, dann ergibt sich 2,435 m (±0,001 m).
  • Gegeben nur ein gültiger Messwert, wenn der Mittelwert berechnet wird, dann erscheint eine Fehlermeldung statt einer Zahl.

Beispiel: Spezifikation für den mittleren Wasserstand

Ziel
  mittlerer_wasserstand(zeiten_h, werte_m)
  für Pegeldaten, Meter über Pegelnull

Funktional
  F1  Die Funktion muss den zeitgewichteten
      Mittelwert (Trapezregel) der gültigen
      Werte liefern.
  F2  FALLS ein Messwert -999 ist, DANN muss
      sie ihn ignorieren.
  F3  FALLS weniger als zwei gültige Werte
      vorliegen, DANN muss sie einen
      ValueError auslösen.
Randbedingungen
  R1  Nur die Python-Standardbibliothek.
  R2  Zeiten in Stunden, aufsteigend.

Nicht-Ziele
  Keine Interpolation, keine Plots,
  Eingaben bleiben unverändert.

Akzeptanz
  A1  Zeiten 0, 1, 2, 6 h; Werte
      2,30; 2,32; -999; 2,60
      ergeben 2,435 m (±0,001 m).

Anthropic: Best practices for Claude Code, 2026

[Anthropic, 2026]

Randbedingungen und Abgrenzung ausdrücklich nennen

Ohne

„Schreibe eine Funktion mittlerer_wasserstand.“

Offen bleiben:

  • welche Bibliotheken erlaubt sind
  • ob die Eingabelisten verändert werden dürfen
  • ob fehlende Werte ergänzt werden sollen

Mit

„Schreibe nur die Funktion mittlerer_wasserstand in pegel.py. Nur Standardbibliothek. Die Eingabelisten nicht verändern. Fehlende Werte nicht ergänzen. Keine weiteren Dateien anlegen.“

Jeder Satz verbietet etwas, das ein Agent sonst plausibel tun würde.

Akzeptanzkriterien werden Tests

Jedes Kriterium ergibt mindestens einen Test:

  • A1: Beispieldaten ergeben 2,435 m
  • F2: Fehlwert −999 wird ignoriert
  • F3: weniger als zwei gültige Werte lösen einen Fehler aus
import pytest
from pegel import mittlerer_wasserstand

def test_beispieldaten():
    z, w = [0, 1, 2, 6], [2.30, 2.32, -999.0, 2.60]
    assert mittlerer_wasserstand(z, w) == pytest.approx(2.435, abs=1e-3)

def test_fehlwert_wird_ignoriert():
    assert mittlerer_wasserstand([0, 1, 2], [2.0, -999.0, 2.0]) == pytest.approx(2.0)

def test_zu_wenige_werte():
    with pytest.raises(ValueError):
        mittlerer_wasserstand([0, 1], [2.0, -999.0])

Prüfung gegen die Spezifikation

Drei Prüfungen

  1. Führen Sie die Tests selbst aus.
  2. Lesen Sie die Änderungen gegen die Spezifikation: Wurde etwas hinzugefügt, das dort nicht steht?
  3. Lassen Sie eine zweite Sitzung ohne den bisherigen Verlauf gegen die Spezifikation prüfen.

Warum

22,6 % der Episoden: Der Agent beschreibt sein Ergebnis ungenauer, als es ist.

Ein Prüfer ohne die Vorgeschichte bewertet nur Ergebnis und Kriterien.

Den Agenten fragen lassen

Vor dem Code

„Ich will [Beschreibung]. Interviewe mich ausführlich. Frage nach Randfällen und Zielkonflikten, nicht nach Offensichtlichem. Schreibe danach eine vollständige Spezifikation in eine Datei.“

Die Spezifikation prüfen Sie gegen das, was Sie gesammelt haben.

Traceability-Dreieck

Regel

Ändert sich die Anforderung, werden Prompt und Test angepasst.

Ändert sich der Test, werden Anforderung und Prompt geprüft.

Kein Test und kein Prompt ohne Anforderung.
