Hörsaalfrage

Sie lassen eine KI das Geometrie-Projekt aus der letzten Vorlesung schreiben. Welche Struktur bekommen Sie zurück und welche wollen Sie?

Zielsetzung

  • Module und Packages unterscheiden und eine Projektstruktur begründen
  • Typische Fehlformen der Aufteilung erkennen und benennen
  • Programme aus mehreren Dateien mit main() und import aufbauen
  • Packages der Standardbibliothek und aus PyPI mit pip oder uv nutzen

Warum Module

Module dienen der Strukturierung

  • Große Programme haben dutzende Klassen und tausende Zeilen: in einer Datei geht der Überblick verloren
  • Arbeiten mehrere Personen an derselben Datei, entstehen Versionskonflikte
  • Deshalb je eine Datei pro Klasse, pro Thema (z.B. Mathematik-Funktionen) oder pro Aufgabenbereich (z.B. Laden getrennt von Verarbeitung)

Die Geometrieklassen kommen aus → 06b_Objects.

Von einer Datei zum Package

Jede .py-Datei ist ein Modul. Unterordner gruppieren Module (points, shapes), zusammen bilden sie das Package geometry.

Grundlagen der Projektstruktur

Allgemeine Struktur

Code in main.py:

import module1
import module2
import helpers

Beispiel Stadtprojekt

Code in city.py:

import buildings
import streets

Die richtige Granularität

Drei Fehlformen bei KI-generiertem Code

A: Alle Klassen in einer Datei, kein Überblick, Konflikte bei gemeinsamer Arbeit

C: Eine Datei pro Methode, die Klasse zerfällt, jede Datei braucht eigene Imports

D: Ein Ordner pro Datei, fünf Ordner bis zur Datei Triangle.py, entsprechend lange Importpfade

Faustregeln für gute Module

  • Die Struktur folgt der Objektorientierung: eine Datei pro Klasse
  • Hilfsfunktionen: eine Datei pro Thema
  • Aufgabenbereiche getrennt: Laden, Verarbeiten, Darstellen
  • Unterpakete in eigenen Unterordnern
  • Zusammengehöriges bleibt zusammen: eine Klasse steht nie in mehreren Dateien
  • Eine Datei hat nicht mehr als 1000 Zeilen

Gliederung im Prompt nennen

Struktur B aus der Hörsaalfrage folgt diesen Regeln. Nennen Sie die gewünschten Module und ihre Aufgaben im Prompt und prüfen Sie die erzeugte Struktur gegen diese Regeln.

Demo: Ein Modul für ein Projekt anfordern

Das Sensorprojekt trennt die Aufgabenbereiche: Laden, Verarbeiten, Darstellen. Der Prompt fordert genau ein Modul an:

„Schreibe sensor_processing.py mit einer Funktion clean_readings(values: list[float]) -> list[float], die Ausreißer entfernt (Werte außerhalb 2σ).“

list[float] ist eine Typangabe: Die Funktion erwartet eine Liste aus Fließkommazahlen und liefert wieder eine solche Liste.

Demo: Das generierte Modul prüfen

# sensor_processing.py  [KI-generiert]
import statistics

def clean_readings(values: list[float]) -> list[float]:
    if len(values) < 2:
        return values
    mean = statistics.mean(values)
    std  = statistics.stdev(values)
    return [v for v in values if abs(v - mean) <= 2 * std]

def _is_outlier(value: float, mean: float, std: float) -> bool:
    return abs(value - mean) > 2 * std
  1. Stimmen Funktionsname und Typen mit dem Prompt überein? Ja.
  2. Passt die Datei an ihren Platz? Ja, sie verarbeitet nur, Laden und Darstellen bleiben in anderen Modulen.
  3. Importiert das Modul nur, was es braucht? Ja, nur statistics.
  4. Ist der Helfer als intern markiert? _is_outlier ja, wird aber nie aufgerufen.

Verhalten mit eigenen Testwerten prüfen: clean_readings([20.0, 20.1, 19.9, 20.0, 99.0]) gibt alle fünf Werte zurück, auch den Ausreißer.

Startpunkt und Import

Die Funktion main() als Startpunkt

  • Python führt die gestartete Datei von oben nach unten aus
  • Üblich ist eine Funktion main() als Startpunkt, in Python nur eine Konvention
  • Beim Import soll main() nicht laufen, deshalb steht am Dateiende eine Verzweigung
def main():
    ...  # Programmablauf

if __name__ == "__main__":
    main()

__name__ ist nur in der gestarteten Datei "__main__", in einer importierten Datei ist es der Modulname.

Best Practice für main()

Vor main() erlaubt

  • Imports und Konstanten
  • Funktions- und Klassendefinitionen

Vor main() vermeiden

  • Globale Variablen
  • Funktionsaufrufe (Nebeneffekte)

Vorteil dieser Struktur

Der Programmfluss bleibt übersichtlich, das Programm ist einfach zu ändern und lässt sich besser wiederverwenden.

Drei Arten zu importieren

Ganzer Pfad

import paket.modul

paket.modul.Klasse(...)

Jeder Zugriff braucht den vollen Pfad.

geometry.points.ImmutablePoint.ImmutablePoint(...)

Mit Alias

import paket.modul as m

m.Klasse(...)

Ein kurzer Name wie m ersetzt den langen Pfad.

point.ImmutablePoint(...)

Einzelne Namen

from paket.modul import Klasse

Klasse(...)

Importiert nur Klasse (* importiert alles, besser vermeiden)

ImmutablePoint(...)

Wie Python ein Modul findet

  • Jeder Teil des Imports ist ein Ordner, zuletzt folgt das Modul (die Datei)
  • Den ersten Ordner (geometry) sucht Python in den Ordnern der Liste sys.path, zuerst im Ordner des gestarteten Programms
  • Findet Python ihn dort nicht, bricht der Import ab, z. B. bei einem Tippfehler:
import geometrie
---------------------------------------------------------------------------
ModuleNotFoundError                       Traceback (most recent call last)
Cell In[9], line 1
----> 1 import geometrie

Paketmanager: pip und uv

Ein Paketmanager lädt Packages aus PyPI und installiert sie mit allen Packages, die diese selbst brauchen: für pandas, plotly und dash insgesamt rund 30.

pip

  • Installiert in die gerade aktive Python-Umgebung
  • Merkt sich nicht, welche Packages und Versionen ein Projekt braucht
  • Pakete und Version speichert man deshalb in requirements.txt
pip install pandas plotly dash

uv

  • Installiert in eine eigene Umgebung pro Projekt (.venv)
  • Trägt die Packages in pyproject.toml ein und die Version in uv.lock
  • Baut die Umgebung auf jedem Rechner gleich auf
uv add pandas plotly dash

Warum die Version zählt

app.run_server() aus älteren dash-Versionen gibt es in Version 4 nicht mehr. Ohne festgehaltene Version läuft ein Programm auf einem anderen Rechner plötzlich nicht mehr.

Lesson Learned

Wie priorisiert man richtig?

Lesson Learned - Priorisierung

  • Das Eisenhower-Schema ordnet Aufgaben nach zwei Merkmalen: dringend und wichtig
  • Wichtig? Was passiert mit dem Ziel, wenn es nicht erledigt wird?
  • Dringend? Gibt es eine Frist, oder wartet etwas darauf?
  • Zuerst die Wichtigkeit prüfen, dann die Dringlichkeit
  • Dringendes meldet sich selbst, Wichtiges braucht Planung
