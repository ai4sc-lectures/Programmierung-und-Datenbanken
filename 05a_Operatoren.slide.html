Ausdrücke und Zuweisung

Anweisungen

Anweisung

Eine Anweisung (engl. statement) stellt eine in der Syntax einer Programmiersprache formulierte einzelne Vorschrift dar, die im Programm nacheinander auszuführen ist.

Beispiel: x = 5 weist der Variablen x den Wert 5 zu.

Ausdrücke

Eine besondere Form von Anweisungen sind Ausdrücke (engl. expression), die immer einen Wert zurückgeben und damit einen Datentyp haben.

Beispiele: 3 + 4 ergibt 7 (int), "Hallo " + "Welt" ergibt einen str.

Operator

Ein Operator ist ein Teil von Ausdrücken und ein Symbol oder Schlüsselwort, das dem Compiler oder Interpreter mitteilt, eine bestimmte Operation auf Werte auszuführen.

Beispiel: In 3 + 4 ist + der Operator, 3 und 4 sind die Operanden.

Variablenzuweisung: Ausdruck rechts, Name links

Bei einer Variablenzuweisung steht der Ausdruck rechts vom Zuweisungsoperator =, der Variablenname links.

Variablenname = Ausdruck

Binäre Addition mit XOR und AND

  • Wiederholung aus 01c_Computerhardware: Binärzahlen werden Stelle für Stelle mit Übertrag Ü addiert
  • Summenbit: A XOR B XOR Ü
  • Übertrag: (A AND B) OR (Ü AND (A XOR B))
  • So addiert auch der Prozessor, Stelle für Stelle

In Python, Bit 0 von 13 + 7:

a, b, ue = True, True, False
(a != b) != ue                  # Summe:    False
(a and b) or (ue and (a != b))  # Übertrag: True

De-Morgan-Regeln

Hilft komplexe Bedingungen umzuschreiben und zu prüfen (wird z.B. in der Logik und beim Reasoning verwendet).

NAND-Regel: not (A and B) = not A or not B

Wir können also statt:

Ich will einen Stuhl, der NICHT aus Holz UND braun ist.

einfacher sagen, dass:

Ich will einen Stuhl, der NICHT aus Holz ODER NICHT braun ist.

A: Holz B: braun not (A and B) not A or not B Ergebnis

NOR-Regel: not (A or B) = not A and not B

Wir können also statt:

Ich will einen Stuhl, der NICHT aus Holz ODER braun ist.

einfacher sagen, dass:

Ich will einen Stuhl, der NICHT aus Holz UND NICHT braun ist.

A: Holz B: braun not (A or B) not A and not B Ergebnis

De-Morgan-Regeln in der Praxis

Compiler

  • Compiler formen Bedingungen mit De Morgan in eine einheitliche Form um (z.B. LLVM für C, C++ und Rust)
  • Diese Schreibweise ergibt performanten Maschinencode ohne Sprung
!((a && b) || (ue && (a != b)))
(!a || !b) && (!ue || a == b)
; clang -O2 (ARM64), für beide Formen gleich:
cmp   w0, #0
ccmp  w1, #0, #4, ne
cset  w8, eq
cmp   w0, w1
ccmp  w2, #0, #4, ne
csel  w0, wzr, w8, ne

Chip

  • NAND- und NOR-Gatter sind auf dem Chip einfacher als AND und OR, die zusätzlich ein NOT brauchen
  • De Morgan: X or Y = not (not X and not Y)
  • So lässt sich jede Logik nur aus NAND (oder nur aus NOR) bauen

Agentischer Arbeitsablauf: Logische Ausdrücke

Agentic Cycle

Wenn KI if not x is None and x > 0.0: generiert: vor dem Ausführen nachverfolgen.

  1. Vergleiche zuerst: x is None und x > 0.0
  2. Dann not auf das Ergebnis von x is None anwenden
  3. Zuletzt and verknüpft beide Teile
  4. Klarere Schreibweise prüfen: x is not None and x > 0.0

Beispiel: Ausdruck nachverfolgen

Gegeben ist dieser Ausdruck:

ergebnis = not x is None and x > 0.0

Wir sagen auf Papier den Wert von ergebnis voraus für

  1. x = 10
  2. x = None
  3. x = "5"

Gehen Sie wie folgt vor:

  1. Operatoren und Rangfolge bestimmen
  2. Jeden Teilausdruck einzeln auswerten
  3. Ergebnis vorhersagen
  4. Erst dann ausführen

Beispiel: Ergebnis der Auswertung

Für x = 10:

x is None      # False
not False      # True
x > 0.0        # True
True and True  # True

Für x = None: not x is None ergibt False. Wegen and wird x > 0.0 nicht mehr ausgewertet, das Ergebnis ist False.

Für x = "5": x is None ist False, not ergibt True, dann scheitert "5" > 0.0 mit einem TypeError.

Klarer schreiben

ergebnis = (x is not None) and (x > 0.0)

Klammern machen die Rangfolge explizit. Der Typ von x bleibt trotzdem zu prüfen.
